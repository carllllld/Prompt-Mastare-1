# Requirements Document: Professional UI Redesign

## Introduction

OptiPrompt currently has a UI that appears "AI-generated and cheap" with excessive colors, borders, padding, and a "tech dashboard" aesthetic. This redesign will transform the interface to match the professional, clean, minimalist style of Swedish real estate agencies like Hemnet and Svensk Fastighetsförmedling (mäklaraktig style).

The redesign focuses on the OptiPrompt form (PromptFormProfessionalV2.tsx) and its associated components, ensuring all text, labels, placeholders, and visual elements feel natural and professionally designed by a Swedish real estate agency rather than generated by AI.

## Glossary

- **UI_System**: The OptiPrompt user interface including all form components, buttons, inputs, and visual elements
- **Form_Component**: React components that make up the property listing form
- **ChipSelector**: Interactive button-like elements for selecting property features
- **Mäklaraktig_Style**: Professional Swedish real estate broker aesthetic (clean, minimal, trustworthy)
- **Design_Token**: CSS/Tailwind classes defining colors, spacing, typography, and borders
- **Label_Text**: User-facing text in form fields, buttons, and instructions
- **Placeholder_Text**: Example text shown in empty input fields
- **Color_Palette**: The set of colors used throughout the interface
- **Typography_System**: Font sizes, weights, and text styling rules
- **Spacing_System**: Padding, margins, and gaps between elements
- **Border_System**: Border widths, colors, and radius values
- **Swedish_Broker_Language**: Natural Swedish language that real estate brokers actually use

## Requirements

### Requirement 1: Color Palette Simplification

**User Story:** As a Swedish real estate broker, I want the interface to use a professional, minimal color palette, so that it looks trustworthy and clean like Hemnet or Svensk Fastighetsförmedling.

#### Acceptance Criteria

1. THE UI_System SHALL use white (#FFFFFF) as the primary background color for 90% of the interface
2. THE UI_System SHALL use subtle gray (#F8F9FA) for secondary backgrounds
3. THE UI_System SHALL use dark gray (#1A1A1A) for primary text instead of pure black
4. THE UI_System SHALL use muted gray (#6B7280) for secondary text and labels
5. THE UI_System SHALL use dark green (#2D5016) exclusively for primary call-to-action buttons
6. THE UI_System SHALL use light gray (#E5E7EB) for all borders
7. THE UI_System SHALL NOT use colored backgrounds (red-50, blue-50, yellow-50, warning-bg, info-bg, success-bg, error-bg)
8. THE UI_System SHALL NOT use colored borders (red-300, blue-300, yellow-300, warning, info, success, error)
9. THE UI_System SHALL use very subtle gray (#F3F4F6) for hover states
10. WHEN a ChipSelector is selected, THE UI_System SHALL use dark green (#2D5016) background with white text
11. WHEN a ChipSelector is unselected, THE UI_System SHALL use white background with gray border

### Requirement 2: Typography Standardization

**User Story:** As a user, I want consistent, readable typography throughout the form, so that the interface feels professionally designed and easy to scan.

#### Acceptance Criteria

1. THE UI_System SHALL use 15px as the standard body text size
2. THE UI_System SHALL use 13px with normal weight and gray color (#6B7280) for all form labels
3. THE UI_System SHALL use 16px with semibold weight for section headings
4. THE UI_System SHALL NOT use uppercase text transformation
5. THE UI_System SHALL use bold weight only for critical emphasis, not for standard labels
6. THE UI_System SHALL use normal font weight for all body text and labels
7. THE UI_System SHALL maintain consistent line-height for readability (1.5 for body, 1.2 for headings)
8. THE UI_System SHALL NOT use more than three font sizes in the entire form

### Requirement 3: Spacing System Refinement

**User Story:** As a user, I want generous white space between sections, so that the form feels clean and uncluttered like professional real estate websites.

#### Acceptance Criteria

1. THE UI_System SHALL use 24px (gap-6) spacing between form sections in normal mode
2. THE UI_System SHALL use 20px-24px (p-5 or p-6) padding inside form sections
3. THE UI_System SHALL use 16px (gap-4) spacing between form fields within a section
4. THE UI_System SHALL NOT use padding smaller than 16px for interactive elements
5. THE UI_System SHALL use 12px (gap-3) spacing between related sub-elements (chips, small labels)
6. THE UI_System SHALL maintain consistent spacing ratios (1:1.5:2 for small:medium:large gaps)
7. WHEN compact mode is enabled, THE UI_System SHALL reduce spacing by 25% while maintaining visual hierarchy

### Requirement 4: Border System Simplification

**User Story:** As a user, I want subtle, consistent borders, so that the interface feels refined and professional rather than busy and cluttered.

#### Acceptance Criteria

1. THE UI_System SHALL use 1px border width for all borders
2. THE UI_System SHALL NOT use 2px or thicker borders
3. THE UI_System SHALL use light gray (#E5E7EB) for all border colors
4. THE UI_System SHALL NOT use colored borders (red, blue, yellow, green)
5. THE UI_System SHALL use minimal border radius (rounded-md or 6px maximum) for form inputs
6. THE UI_System SHALL use rounded-lg (8px) for buttons and chips
7. THE UI_System SHALL NOT use fully rounded corners (rounded-full) except for ChipSelector elements
8. THE UI_System SHALL use consistent border-radius values across similar component types

### Requirement 5: Button Design Standardization

**User Story:** As a user, I want buttons that look professional and clear, so that I understand which actions are primary and which are secondary.

#### Acceptance Criteria

1. WHEN a button is a primary action, THE UI_System SHALL use dark green (#2D5016) background with white text
2. WHEN a button is a secondary action, THE UI_System SHALL use white background with gray border and gray text
3. THE UI_System SHALL use 12px horizontal padding and 24px vertical padding (px-6 py-3) for standard buttons
4. THE UI_System SHALL NOT include icons in buttons unless absolutely necessary for clarity
5. THE UI_System SHALL use subtle darkening (10%) on hover for primary buttons
6. THE UI_System SHALL use subtle gray background (#F3F4F6) on hover for secondary buttons
7. THE UI_System SHALL NOT use shadows on buttons except for sticky footer/header elements
8. THE UI_System SHALL use text-only buttons without background for tertiary actions
9. THE UI_System SHALL disable buttons with gray background (#D1D5DB) and not-allowed cursor

### Requirement 6: ChipSelector Component Neutralization

**User Story:** As a user, I want feature selection chips to be clean and neutral, so that they don't distract with unnecessary colors.

#### Acceptance Criteria

1. WHEN a chip is unselected, THE ChipSelector SHALL display white background with light gray border (#E5E7EB)
2. WHEN a chip is selected, THE ChipSelector SHALL display dark green background (#2D5016) with white text
3. THE ChipSelector SHALL include a checkmark icon (✓) when selected
4. THE ChipSelector SHALL NOT use colored variants (warning-bg, info-bg, success-bg, error-bg)
5. THE ChipSelector SHALL use 12px text size (text-xs)
6. THE ChipSelector SHALL use rounded-full border radius
7. THE ChipSelector SHALL use 12px horizontal and 8px vertical padding (px-3 py-2)
8. THE ChipSelector SHALL show subtle hover state with gray background (#F3F4F6) when unselected
9. THE ChipSelector SHALL maintain minimum 44px touch target for accessibility
10. THE ChipSelector SHALL display tooltip on hover if additional information is available

### Requirement 7: Form Input Standardization

**User Story:** As a user, I want form inputs that are clear and easy to use, so that I can efficiently enter property information.

#### Acceptance Criteria

1. THE Form_Component SHALL use 40px height (h-10) for standard text inputs
2. THE Form_Component SHALL use 36px height (h-9) for compact mode inputs
3. THE Form_Component SHALL use light gray border (#E5E7EB) for input borders
4. THE Form_Component SHALL use 12px horizontal padding (px-3) for inputs
5. THE Form_Component SHALL use rounded-md (6px) border radius for inputs
6. THE Form_Component SHALL display placeholder text in italic style with muted gray color
7. THE Form_Component SHALL hide placeholder text when input is focused
8. THE Form_Component SHALL use 2px ring with primary color on focus
9. THE Form_Component SHALL NOT use colored borders for validation states in default state
10. WHEN an input has an error, THE Form_Component SHALL display error message below input in small red text

### Requirement 8: Label and Placeholder Text Naturalization

**User Story:** As a Swedish real estate broker, I want all text to sound natural and professional, so that it doesn't feel AI-generated or awkward.

#### Acceptance Criteria

1. THE UI_System SHALL use natural Swedish language that real estate brokers actually use
2. THE UI_System SHALL NOT use overly formal or technical language in labels
3. THE UI_System SHALL NOT use AI-generated phrases that sound unnatural
4. THE UI_System SHALL use concise, clear labels without unnecessary words
5. THE Placeholder_Text SHALL provide realistic examples that brokers would actually write
6. THE Placeholder_Text SHALL NOT use generic or vague examples
7. THE Label_Text SHALL use sentence case, not title case or uppercase
8. THE UI_System SHALL use consistent terminology throughout (e.g., always "boarea" not mixing with "boyta")
9. THE UI_System SHALL use standard Swedish real estate terminology (e.g., "avgift" for apartments, "driftskostnad" for houses)
10. THE UI_System SHALL review all labels and placeholders from a Swedish broker's perspective

### Requirement 9: Section Header Simplification

**User Story:** As a user, I want section headers that are clear but not overwhelming, so that I can quickly understand the form structure.

#### Acceptance Criteria

1. THE Form_Component SHALL use 16px semibold text for section headers
2. THE Form_Component SHALL use dark gray (#1A1A1A) color for section headers
3. THE Form_Component SHALL use 16px bottom margin (mb-4) below section headers
4. THE Form_Component SHALL NOT use colored backgrounds for section headers
5. THE Form_Component SHALL NOT use uppercase text for section headers
6. THE Form_Component SHALL NOT use icons in section headers unless necessary for clarity
7. THE Form_Component SHALL align section headers to the left
8. THE Form_Component SHALL use consistent header styling across all sections

### Requirement 10: Progress Indicator Refinement

**User Story:** As a user, I want a subtle progress indicator, so that I know my completion status without visual clutter.

#### Acceptance Criteria

1. THE UI_System SHALL display progress as a horizontal bar with percentage
2. THE UI_System SHALL use light gray (#E5E7EB) for incomplete progress background
3. THE UI_System SHALL use dark green (#2D5016) for completed progress
4. THE UI_System SHALL display completion count as "X / Y fält" in small gray text
5. THE UI_System SHALL NOT use colored badges or labels for priority levels
6. THE UI_System SHALL use subtle visual indicators for field priority (thin left border)
7. THE UI_System SHALL display critical fields with amber left border (#F59E0B)
8. THE UI_System SHALL display important fields with green left border (#10B981)
9. THE UI_System SHALL display optional fields with gray left border (#9CA3AF)
10. THE UI_System SHALL make priority items clickable to scroll to the field

### Requirement 11: Sticky Header and Footer Consistency

**User Story:** As a user, I want the sticky header and footer to be clean and unobtrusive, so that they provide utility without dominating the screen.

#### Acceptance Criteria

1. THE UI_System SHALL use white background for sticky header and footer
2. THE UI_System SHALL use subtle shadow (shadow-sm) for sticky elements
3. THE UI_System SHALL use light gray border (#E5E7EB) for top/bottom borders
4. THE UI_System SHALL display control buttons as text-only with hover states
5. THE UI_System SHALL use dark green (#2D5016) for the primary submit button in footer
6. THE UI_System SHALL use 16px padding (p-4) in sticky header and footer
7. THE UI_System SHALL NOT use colored backgrounds or heavy shadows
8. THE UI_System SHALL maintain consistent styling with the rest of the form

### Requirement 12: Collapsible Section Design

**User Story:** As a user, I want collapsible sections that are easy to identify and interact with, so that I can manage form complexity.

#### Acceptance Criteria

1. THE Form_Component SHALL display collapse/expand indicator as simple arrow (▼/▲)
2. THE Form_Component SHALL use gray color (#9CA3AF) for collapse indicators
3. THE Form_Component SHALL show subtle hover background (#F3F4F6) on section headers
4. THE Form_Component SHALL display completion percentage in small gray text next to section title
5. THE Form_Component SHALL show checkmark icon when section is 100% complete
6. THE Form_Component SHALL NOT use colored backgrounds for collapsed sections
7. THE Form_Component SHALL maintain consistent border styling when collapsed or expanded
8. THE Form_Component SHALL use smooth transition (200ms) for collapse/expand animation

### Requirement 13: Image Upload Section Refinement

**User Story:** As a user, I want the image upload area to be clean and professional, so that it matches the overall aesthetic.

#### Acceptance Criteria

1. THE Form_Component SHALL display image thumbnails with light gray border
2. THE Form_Component SHALL use white background for image upload area
3. THE Form_Component SHALL display upload progress with simple progress bar
4. THE Form_Component SHALL use dark green (#2D5016) for upload progress indicator

6. THE Form_Component SHALL NOT use colored backgrounds or heavy borders for image area

### Requirement 14: Tooltip Design Simplification

**User Story:** As a user, I want helpful tooltips that are subtle and professional, so that I can get information without visual distraction.

#### Acceptance Criteria

1. THE UI_System SHALL display tooltips with white background and subtle shadow
2. THE UI_System SHALL use 12px text size (text-xs) for tooltip content
3. THE UI_System SHALL use dark gray (#1A1A1A) text in tooltips
4. THE UI_System SHALL use light gray border (#E5E7EB) for tooltips
5. THE UI_System SHALL position tooltips above or below the trigger element
6. THE UI_System SHALL show tooltips on hover with 200ms delay
7. THE UI_System SHALL NOT use colored backgrounds for tooltips
8. THE UI_System SHALL limit tooltip width to 320px (max-w-xs) for readability

### Requirement 15: Alert and Dialog Consistency

**User Story:** As a user, I want alerts and dialogs to match the professional aesthetic, so that the experience is consistent.

#### Acceptance Criteria

1. THE UI_System SHALL use white background for dialog boxes
2. THE UI_System SHALL use light gray border (#E5E7EB) for dialogs
3. THE UI_System SHALL use dark gray (#1A1A1A) for dialog titles

5. THE UI_System SHALL use dark green (#2D5016) for primary dialog actions
6. THE UI_System SHALL use gray outline button for secondary dialog actions
7. THE UI_System SHALL NOT use colored backgrounds (red, yellow, blue) for alert types
8. THE UI_System SHALL use subtle left border with color to indicate alert type (error: red, warning: amber, info: blue, success: green)
9. THE UI_System SHALL use 16px padding (p-4) in dialogs
10. THE UI_System SHALL display close button as simple X icon in gray

### Requirement 16: Responsive Design Maintenance

**User Story:** As a user on mobile or tablet, I want the redesigned interface to work perfectly on my device, so that I can use it anywhere.

#### Acceptance Criteria

1. THE UI_System SHALL maintain 3-column layout on desktop (≥1024px)
2. THE UI_System SHALL use 2-column layout on tablet (768px-1023px)
3. THE UI_System SHALL use 1-column layout on mobile (<768px)
4. THE UI_System SHALL maintain minimum 44px touch targets on mobile
5. THE UI_System SHALL adjust padding to 16px (p-4) on mobile devices
6. THE UI_System SHALL stack buttons vertically on mobile
7. THE UI_System SHALL maintain readability with consistent font sizes across devices
8. THE UI_System SHALL ensure sticky header and footer work properly on mobile

### Requirement 17: Accessibility Compliance

**User Story:** As a user with accessibility needs, I want the interface to be fully accessible, so that I can use it effectively with assistive technology.

#### Acceptance Criteria

1. THE UI_System SHALL maintain WCAG 2.1 AA contrast ratios for all text
2. THE UI_System SHALL provide keyboard navigation for all interactive elements
3. THE UI_System SHALL display focus indicators (2px ring) on all focusable elements
4. THE UI_System SHALL include ARIA labels for all form fields
5. THE UI_System SHALL provide ARIA attributes for collapsible sections
6. THE UI_System SHALL ensure ChipSelector elements have role="checkbox" and aria-checked
7. THE UI_System SHALL announce form validation errors to screen readers
8. THE UI_System SHALL maintain logical tab order throughout the form
9. THE UI_System SHALL support keyboard shortcuts (Cmd/Ctrl+Enter to submit)
10. THE UI_System SHALL ensure all interactive elements are reachable via keyboard

### Requirement 18: Component Library Updates

**User Story:** As a developer, I want the base UI components updated to match the new design system, so that consistency is maintained automatically.

#### Acceptance Criteria

1. THE Button component SHALL implement the new color palette and styling rules
2. THE Input component SHALL implement the new border and spacing rules
3. THE Textarea component SHALL implement consistent styling with Input
4. THE Select component SHALL implement consistent styling with Input
5. THE Badge component SHALL be removed or neutralized (gray only)
6. THE Card component SHALL use white background with light gray border
7. THE Alert component SHALL use subtle left border for type indication
8. THE Dialog component SHALL use white background with subtle shadow
9. THE Tooltip component SHALL use white background with light gray border
10. THE UI_System SHALL remove or update any components using old color schemes

### Requirement 19: Form Validation Visual Feedback

**User Story:** As a user, I want clear but subtle validation feedback, so that I know what needs to be corrected without visual overwhelm.

#### Acceptance Criteria

1. WHEN a required field is empty and form is submitted, THE UI_System SHALL display error message below the field
2. THE UI_System SHALL use red text (#DC2626) for error messages
3. THE UI_System SHALL use 12px text size (text-xs) for error messages
4. THE UI_System SHALL NOT use red borders on inputs in default state
5. THE UI_System SHALL scroll to the first error field when validation fails
6. THE UI_System SHALL display toast notification with list of missing required fields
7. THE UI_System SHALL use white background with subtle border for toast notifications
8. THE UI_System SHALL NOT use colored backgrounds for toast notifications
9. THE UI_System SHALL clear error messages when user starts typing in the field
10. THE UI_System SHALL maintain error state until field is valid

### Requirement 20: Import Integration Buttons

**User Story:** As a user, I want import buttons (Hemnet, Vitec) to match the professional design, so that they integrate seamlessly.

#### Acceptance Criteria

1. THE UI_System SHALL style Hemnet import button as secondary button (white with gray border)
2. THE UI_System SHALL style Vitec import button as secondary button (white with gray border)
3. THE UI_System SHALL display import buttons with consistent spacing (gap-2)
4. THE UI_System SHALL use 14px text size for import button labels
5. THE UI_System SHALL show loading state with subtle spinner (no colored backgrounds)
6. THE UI_System SHALL NOT use brand colors for import buttons
7. THE UI_System SHALL use gray icon color matching the text
8. THE UI_System SHALL maintain consistent button height (h-10) with other buttons

### Requirement 21: Swedish Language Quality Review

**User Story:** As a Swedish real estate broker, I want all interface text reviewed by someone with real estate experience, so that it sounds authentic and professional.

#### Acceptance Criteria

1. THE UI_System SHALL have all Label_Text reviewed for natural Swedish language
2. THE UI_System SHALL have all Placeholder_Text reviewed for realistic examples
3. THE UI_System SHALL have all button text reviewed for clarity and professionalism
4. THE UI_System SHALL have all section titles reviewed for broker terminology
5. THE UI_System SHALL have all error messages reviewed for helpful, natural language
6. THE UI_System SHALL have all tooltip text reviewed for accuracy and clarity
7. THE UI_System SHALL replace any AI-generated sounding phrases with natural alternatives
8. THE UI_System SHALL ensure consistency in terminology across all text
9. THE UI_System SHALL use standard Swedish real estate abbreviations (e.g., "kvm" not "m²")
10. THE UI_System SHALL avoid overly technical or formal language in user-facing text

### Requirement 22: Performance and Animation Refinement

**User Story:** As a user, I want smooth, subtle animations that enhance the experience, so that the interface feels polished without being distracting.

#### Acceptance Criteria

1. THE UI_System SHALL use 200ms transition duration for hover states
2. THE UI_System SHALL use 200ms transition duration for collapse/expand animations
3. THE UI_System SHALL use ease-in-out timing function for all transitions
4. THE UI_System SHALL respect prefers-reduced-motion user preference
5. THE UI_System SHALL NOT use bounce, slide, or complex animations
6. THE UI_System SHALL use simple fade transitions for tooltips and dialogs
7. THE UI_System SHALL use transform transitions for collapse/expand (not height)
8. THE UI_System SHALL maintain 60fps performance during animations
9. THE UI_System SHALL NOT animate color changes (use instant transitions)
10. THE UI_System SHALL use subtle opacity changes (0.9-1.0) for hover states

### Requirement 23: Print and Export Styling

**User Story:** As a user, I want the form to look professional when printed or exported, so that I can share it with colleagues.

#### Acceptance Criteria

1. WHEN print mode is activated, THE UI_System SHALL expand all collapsed sections
2. WHEN print mode is activated, THE UI_System SHALL hide interactive controls (expand/collapse buttons)
3. WHEN print mode is activated, THE UI_System SHALL use black text on white background
4. WHEN print mode is activated, THE UI_System SHALL remove shadows and hover states
5. WHEN print mode is activated, THE UI_System SHALL maintain section borders for structure
6. THE UI_System SHALL use print-friendly spacing (reduce to 12px gaps)
7. THE UI_System SHALL ensure all text is readable in print (minimum 12px)
8. THE UI_System SHALL hide sticky header and footer in print mode
9. THE UI_System SHALL display all selected chips as comma-separated text in print mode
10. THE UI_System SHALL restore normal view when print mode is deactivated

### Requirement 24: Dark Mode Consideration (Future)

**User Story:** As a user who prefers dark mode, I want the design system to support future dark mode implementation, so that I can use my preferred theme.

#### Acceptance Criteria

1. THE UI_System SHALL use CSS custom properties for all colors
2. THE UI_System SHALL use semantic color names (primary, secondary, accent) not literal colors in component code
3. THE UI_System SHALL structure color tokens to support light/dark variants
4. THE UI_System SHALL ensure all color combinations maintain WCAG AA contrast in light mode
5. THE UI_System SHALL document color token structure for future dark mode implementation
6. THE UI_System SHALL NOT hardcode hex colors in component JSX (use Tailwind classes or CSS variables)
7. THE UI_System SHALL test that all components work with inverted color schemes
8. THE UI_System SHALL ensure images and icons work on both light and dark backgrounds

**User Story:** As a developer, I want clear documentation of the new design system, so that I can maintain consistency when adding new features.

#### Acceptance Criteria

1. THE UI_System SHALL document all color tokens with hex values and usage guidelines
2. THE UI_System SHALL document all typography scales with sizes and use cases
3. THE UI_System SHALL document all spacing values with examples
4. THE UI_System SHALL document all border styles with examples
5. THE UI_System SHALL provide component usage examples for all redesigned components
6. THE UI_System SHALL document the mäklaraktig design philosophy and principles
7. THE UI_System SHALL provide before/after examples for key components
8. THE UI_System SHALL document accessibility requirements for new components
9. THE UI_System SHALL provide Figma or design file reference (if available)
10. THE UI_System SHALL include code snippets for common patterns (buttons, inputs, sections)
