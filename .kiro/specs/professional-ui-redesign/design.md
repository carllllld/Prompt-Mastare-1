# Design Document: Professional UI Redesign (Mäklaraktig Style)

## Overview

This design transforms OptiPrompt from its current "AI-generated and cheap" appearance into a professional, clean, minimalist interface that matches the aesthetic of Swedish real estate agencies like Hemnet and Svensk Fastighetsförmedling—what we call "mäklaraktig" (broker-like) style.

The redesign focuses on radical simplification: white backgrounds, subtle gray accents, minimal color usage (only dark green for CTAs), generous white space, and natural Swedish language. The goal is to create an interface that looks professionally designed by a Swedish real estate agency, not generated by AI.

### Current State Problems

The existing UI has:
- Excessive colors (red-50, blue-50, yellow-50, warning-bg, info-bg, success-bg, error-bg)
- Colored borders (red-300, blue-300, yellow-300) that look "tech dashboard"
- Too many font sizes and weights
- Uppercase text that feels aggressive
- Heavy borders (2px) and excessive rounded corners
- Colored badges and labels everywhere
- Icons in every button
- Small padding creating cramped feeling
- "AI-generated" looking text and labels

### Design Philosophy: Mäklaraktig (Swedish Real Estate Broker Style)

The mäklaraktig aesthetic is characterized by:

1. **Extreme Color Restraint**: 90% white, subtle gray accents, ONE accent color (dark green) used sparingly
2. **Generous White Space**: Breathing room between elements, never cramped
3. **Minimal Typography**: One body size (15px), consistent labels (13px), simple headings (16px)
4. **Subtle Borders**: 1px light gray borders, no colored borders
5. **No Visual Noise**: No colored backgrounds, no badges, minimal icons
6. **Professional Language**: Natural Swedish that real brokers actually use
7. **Clean Simplicity**: If it's not essential, remove it

### Design Goals

1. **Look Professionally Designed**: Not AI-generated, not "tech startup"
2. **Inspire Trust**: Swedish brokers should feel this is a professional tool
3. **Radical Simplification**: Remove 80% of current visual complexity
4. **Natural Language**: All text should sound like a real Swedish broker wrote it
5. **Hemnet/SvenskaFast Aesthetic**: Match the clean, minimal style of top Swedish real estate sites

## Architecture

### Design System Foundation

The mäklaraktig redesign is built on radical simplification:

1. **Color Palette Layer**: Minimal colors
   - White (#FFFFFF) - 90% of interface
   - Subtle gray (#F8F9FA) - secondary backgrounds
   - Dark gray (#1A1A1A) - primary text
   - Muted gray (#6B7280) - secondary text/labels
   - Dark green (#2D5016) - ONLY for primary CTAs
   - Light gray (#E5E7EB) - ALL borders

2. **Typography Layer**: Three sizes maximum
   - Body: 15px (readable, professional)
   - Labels: 13px normal weight, gray
   - Headings: 16px semibold, dark gray
   - NO uppercase, minimal bold

3. **Spacing Layer**: Generous white space
   - 24px between sections
   - 20-24px padding inside sections
   - 16px between form fields
   - Never cramped, always breathing room

4. **Border Layer**: Subtle and consistent
   - 1px width (never 2px)
   - Light gray (#E5E7EB) color
   - Minimal radius (6-8px max)
   - NO colored borders

### Technology Stack

- **Styling**: Tailwind CSS with custom mäklaraktig tokens
- **UI Primitives**: Radix UI (existing)
- **Typography**: System sans-serif (no custom fonts needed)
- **Icons**: Lucide React (minimal usage)
- **Animations**: Subtle 200ms transitions only

**Border Color** (All borders use this)


**Hover States** (Very subtle)
```css
--accent: 220 13% 96%;            /* Very subtle gray #F3F4F6 */

```

#### Semantic Colors (Minimal, Text-Only Usage)

**Success** (For validation messages only)
```css
--success: 142 71% 45%;           /* Green #10B981 */
--success-bg: 142 76% 96%;        /* Very light green bg (rare) */
```

**Warning** (For critical field indicators only)
```css

```

**Error** (For error messages only)
```css

--error-bg: 0 86% 97%;            /* Very light red bg (rare) */
```

**Info** (For informational text only)
```css
--info: 199 89% 48%;              /* Cyan #0EA5E9 */
--info-bg: 199 95% 96%;           /* Very light cyan bg (rare) */
```

#### What NOT to Use

❌ NO colored backgrounds (red-50, blue-50, yellow-50)
❌ NO colored borders (red-300, blue-300, yellow-300)
❌ NO colored badges or labels
❌ NO multiple accent colors
❌ NO gradients or complex color schemes

#### Color Usage Rules

1. **90% White Rule**: 90% of the interface should be white or very subtle gray
2. **One Accent Rule**: Dark green (#2D5016) is the ONLY accent color, used ONLY for primary CTAs
3. **Gray Borders Only**: All borders are light gray (#E5E7EB), never colored
4. **Semantic Colors for Text**: Success/warning/error colors ONLY for text messages, never for backgrounds or borders in default state
5. **Hover is Subtle**: Hover states use very subtle gray (#F3F4F6), not color changes

#### Typography Scale (Minimal Sizes)

**Font Families** (System fonts, no custom fonts needed)
```css
--font-sans: system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif;
```

**Font Sizes** (Only 3 sizes)
```css
--text-xs: 0.75rem;      /* 12px - minimum for small text */
--text-sm: 0.8125rem;    /* 13px - labels, secondary text */
--text-base: 0.9375rem;  /* 15px - body text (standard) */
--text-md: 1rem;         /* 16px - section headings */
```

**Font Weights** (Minimal usage)
```css
--font-normal: 400;      /* Default for all text */
--font-medium: 500;      /* Rare, for emphasis */
--font-semibold: 600;    /* Only for headings */
```

**Line Heights**
```css
--leading-normal: 1.5;   /* Body text */
--leading-snug: 1.2;     /* Headings */
```

#### Typography Rules

1. **Three Sizes Maximum**: 13px labels, 15px body, 16px headings
2. **No Uppercase**: All text in sentence case
3. **Minimal Bold**: Normal weight for everything except headings
4. **No Italic**: Except for placeholder text
5. **Gray Labels**: All form labels in muted gray (#6B7280), not black

#### Spacing Scale (Generous White Space)

Use Tailwind's 4px-based scale with emphasis on generous spacing:

**Standard Spacing**
- `space-3` = 12px (minimum gap between chips/small elements)
- `space-4` = 16px (gap between form fields)
- `space-5` = 20px (padding inside sections)
- `space-6` = 24px (gap between sections)
- `space-8` = 32px (large section spacing)

**Padding Rules**
- Form sections: p-5 or p-6 (20-24px)
- Inputs: px-3 (12px horizontal)
- Buttons: px-6 py-3 (24px horizontal, 12px vertical)
- Never less than 16px for interactive elements

**Gap Rules**
- Between sections: gap-6 (24px)
- Between form fields: gap-4 (16px)
- Between chips: gap-3 (12px)
- Between related elements: gap-2 (8px)

#### Shadow Scale (Minimal Usage)

Shadows only for sticky elements and subtle elevation:

```css
--shadow-sm: 0 1px 2px 0 rgb(0 0 0 / 0.05);  /* Subtle cards */
--shadow-md: 0 2px 4px 0 rgb(0 0 0 / 0.08);  /* Sticky header/footer */
```

❌ NO heavy shadows (shadow-lg, shadow-xl)
❌ NO shadows on buttons (except sticky elements)
❌ NO colored shadows

#### Border Radius (Minimal)

```css
--radius-md: 0.375rem;   /* 6px - inputs */
--radius-lg: 0.5rem;     /* 8px - buttons, chips */
```

❌ NO fully rounded corners (rounded-full) except for ChipSelector
❌ NO large radius (rounded-xl, rounded-2xl)
❌ Keep it subtle and professional

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system—essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

### Property Reflection

After analyzing all 25 requirements with 200+ acceptance criteria, I identified significant redundancy:

**Redundancy Group 1: Color Consistency**
- Requirements 1.6, 4.3 both test that borders use light gray
- Requirements 1.8, 4.4 both test absence of colored borders
- Combined into: "All borders use light gray, no colored borders"

**Redundancy Group 2: Border Width**
- Requirements 4.1, 4.2 both test 1px border width
- Combined into: "All borders use 1px width"

**Redundancy Group 3: Typography Sizes**
- Requirements 2.1, 2.2, 2.3, 2.8 all test font size consistency
- Combined into: "Only three font sizes used (13px, 15px, 16px)"

**Redundancy Group 4: Spacing Consistency**
- Requirements 3.1, 3.2, 3.3, 3.5 all test spacing values
- Combined into: "Spacing follows consistent scale (12px, 16px, 20-24px, 24px)"

**Redundancy Group 5: Component State Examples**
- Requirements 1.10-1.11, 5.1-5.2, 5.8-5.9, 6.1-6.2, 7.1-7.3 are specific state examples
- These are better tested as unit tests, not properties
- Properties should test consistency across ALL instances

After reflection, I will write 20 unique properties that provide comprehensive coverage without redundancy.

### Property 1: White Background Dominance

*For any* page or component in the application, at least 90% of the visible area should use white (#FFFFFF) or subtle gray (#F8F9FA) backgrounds, not colored backgrounds

**Validates: Requirements 1.1, 1.2, 1.7**

### Property 2: Text Color Consistency

*For any* text element, the color should be either dark gray (#1A1A1A) for primary text or muted gray (#6B7280) for secondary text/labels, never pure black (#000000)

**Validates: Requirements 1.3, 1.4**

### Property 3: Accent Color Exclusivity

*For any* element using dark green (#2D5016), it should be a primary call-to-action button or selected chip, never used for decorative purposes or secondary elements

**Validates: Requirements 1.5, 1.10**

### Property 4: Border Color Uniformity

*For any* element with a border, the border color should be light gray (#E5E7EB), never colored (red, blue, yellow, green, etc.)

**Validates: Requirements 1.6, 1.8, 4.3, 4.4**

### Property 5: Hover State Subtlety

*For any* interactive element, hover states should use very subtle gray (#F3F4F6) background, not color changes or heavy effects

**Validates: Requirements 1.9, 5.6**

### Property 6: Typography Size Limitation

*For any* text element in form components, the font size should be one of exactly three values: 13px (labels), 15px (body), or 16px (headings)

**Validates: Requirements 2.1, 2.2, 2.3, 2.8**

### Property 7: Uppercase Elimination

*For any* text element, the text-transform property should not be 'uppercase', all text should use sentence case

**Validates: Requirements 2.4**

### Property 8: Font Weight Restraint

*For any* form label or body text, the font weight should be normal (400), with semibold (600) reserved only for section headings

**Validates: Requirements 2.5, 2.6**

### Property 9: Line Height Consistency

*For any* text element, body text should use line-height 1.5 and headings should use line-height 1.2

**Validates: Requirements 2.7**

### Property 10: Spacing Scale Adherence

*For any* container with spacing, the gap or padding values should follow the scale: 12px (gap-3), 16px (gap-4), 20-24px (p-5/p-6), 24px (gap-6)

**Validates: Requirements 3.1, 3.2, 3.3, 3.5, 3.6**

### Property 11: Minimum Interactive Padding

*For any* interactive element (button, input, chip), the padding should be at least 16px in any direction

**Validates: Requirements 3.4**

### Property 12: Compact Mode Proportionality

*For any* spacing value in compact mode, it should be 75% of the normal mode value (25% reduction)

**Validates: Requirements 3.7**

### Property 13: Border Width Uniformity

*For any* element with a border, the border width should be 1px, never 2px or thicker

**Validates: Requirements 4.1, 4.2**

### Property 14: Border Radius Consistency

*For any* form input, the border radius should be rounded-md (6px); for any button or chip, it should be rounded-lg (8px); rounded-full should only appear on ChipSelector elements

**Validates: Requirements 4.5, 4.6, 4.7, 4.8**

### Property 15: Button Padding Standardization

*For any* standard button, the padding should be px-6 py-3 (24px horizontal, 12px vertical)

**Validates: Requirements 5.3**

### Property 16: Icon Minimization in Buttons

*For any* button element, it should not contain icon children unless it's an icon-only button or the icon is essential for clarity (less than 20% of buttons should have icons)

**Validates: Requirements 5.4**

### Property 17: Shadow Restriction

*For any* button element, it should not have shadow classes (shadow-sm, shadow-md, etc.) unless it's part of a sticky header or footer

**Validates: Requirements 5.7**

### Property 18: Input Height Consistency

*For any* text input element, the height should be h-10 (40px) in normal mode or h-9 (36px) in compact mode

**Validates: Requirements 7.1, 7.2**

### Property 19: Placeholder Styling

*For any* input element with placeholder text, the placeholder should use italic style and muted gray color, and should hide on focus (focus:placeholder-transparent)

**Validates: Requirements 7.6, 7.7**

### Property 20: Focus Ring Consistency

*For any* input element, focus states should include ring-2 and ring-primary classes

**Validates: Requirements 7.8**

### Property 21: Section Header Uniformity

*For any* section header, it should use text-md (16px), font-semibold, dark gray color, and mb-4 spacing, with no uppercase or colored backgrounds

**Validates: Requirements 9.1, 9.2, 9.3, 9.4, 9.5**

### Property 22: Progress Bar Simplicity

*For any* progress indicator, the incomplete background should be light gray (#E5E7EB) and the completed fill should be dark green (#2D5016), with no colored variants

**Validates: Requirements 10.2, 10.3, 10.5**

### Property 23: Sticky Element Consistency

*For any* sticky header or footer, it should use white background, light gray border, subtle shadow (shadow-sm), and 16px padding

**Validates: Requirements 11.1, 11.2, 11.3, 11.6**

### Property 24: Tooltip Minimalism

*For any* tooltip element, it should use white background, light gray border, subtle shadow, 12px text, and max-width of 320px

**Validates: Requirements 14.1, 14.2, 14.3, 14.4, 14.8**

### Property 25: Alert Left Border Pattern

*For any* alert or dialog with semantic meaning, it should use a subtle left border (border-l-4) with semantic color, but white background (no colored backgrounds like red-50, yellow-50)

**Validates: Requirements 15.7, 15.8**

### Property 26: Responsive Breakpoint Standards

*For any* responsive class, the breakpoint prefix should be one of Tailwind's standard breakpoints: sm:, md:, lg:, xl:, or 2xl:

**Validates: Requirements 16.1, 16.2, 16.3**

### Property 27: Mobile Touch Target Minimum

*For any* interactive element on mobile viewports (<768px), the minimum height and width should be 44px

**Validates: Requirements 16.4**

### Property 28: WCAG Contrast Compliance

*For any* text-background color combination, the contrast ratio should meet WCAG 2.1 AA standards (4.5:1 for normal text, 3:1 for large text)

**Validates: Requirements 17.1**

### Property 29: Keyboard Navigation Completeness

*For any* interactive element, it should be reachable via keyboard navigation (Tab key) and have visible focus indicators

**Validates: Requirements 17.2, 17.3, 17.8**

### Property 30: ARIA Attribute Presence

*For any* form field, it should have appropriate ARIA labels or associated label elements for screen reader accessibility

## Error Handling

### Design System Validation Errors

**Colored Background Detection**
- Error: Component uses colored background (red-50, blue-50, yellow-50, etc.)
- Handling: ESLint rule detects colored background classes during development
- Recovery: Provide error message with file location and suggest white or subtle gray alternative

**Colored Border Detection**
- Error: Component uses colored border (red-300, blue-300, border-warning, etc.)
- Handling: ESLint rule detects colored border classes
- Recovery: Fail build with message to use border-gray-300 instead

**Font Size Violation**
- Error: Component uses font size other than 13px, 15px, or 16px
- Handling: ESLint rule detects non-standard font sizes
- Recovery: Provide error message suggesting text-sm, text-base, or text-md

**Uppercase Text Detection**
- Error: Component uses uppercase text transformation
- Handling: ESLint rule detects uppercase class
- Recovery: Fail build with message to use sentence case

**Thick Border Detection**
- Error: Component uses border-2 or thicker
- Handling: ESLint rule detects thick border classes
- Recovery: Provide error message to use border (1px) instead

### Component Variant Errors

**Invalid Button Variant**
- Error: Button receives variant other than primary, secondary, or text
- Handling: TypeScript type checking catches invalid variants at compile time
- Recovery: Show TypeScript error with valid variant options (primary, secondary, text)

**Missing Accessibility Props**
- Error: Interactive element missing required ARIA attributes

### Test Utilities

**Contrast Ratio Calculator**
```typescript
function calculateContrastRatio(color1: string, color2: string): number {
  const lum1 = getRelativeLuminance(color1);
  const lum2 = getRelativeLuminance(color2);
  
  const lighter = Math.max(lum1, lum2);
  const darker = Math.min(lum1, lum2);
  
  return (lighter + 0.05) / (darker + 0.05);
}

function getRelativeLuminance(hex: string): number {
  // Remove # if present
  hex = hex.replace('#', '');
  
  // Convert to RGB
  const r = parseInt(hex.substr(0, 2), 16) / 255;
  const g = parseInt(hex.substr(2, 2), 16) / 255;
  const b = parseInt(hex.substr(4, 2), 16) / 255;
  
  // Apply gamma correction
  const [rLinear, gLinear, bLinear] = [r, g, b].map(channel => {
    return channel <= 0.03928
      ? channel / 12.92
      : Math.pow((channel + 0.055) / 1.055, 2.4);
  });
  
  // Calculate relative luminance
  return 0.2126 * rLinear + 0.7152 * gLinear + 0.0722 * bLinear;
}
```
